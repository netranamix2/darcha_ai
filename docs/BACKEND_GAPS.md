# Аудит интеграции Darcha

Сверены маршруты FastAPI, их схемы и модели, контракт интерфейса и API-клиент. Проверка по исходникам бэкенда из коммита `f2747a1`. [Маршруты](../backend/app/main.py#L63) · [Модели](../backend/app/db/models.py) · [Типы](../frontend/src/api/types.ts) · [Клиент](../frontend/src/api/client.ts)

**P1** — для сквозного демо на реальном API. **P2** — для полноты интеграции.

Клиент приводит ответы к типам интерфейса. При HTTP 404, HTTP 501 или сетевой ошибке используется мок для данного эндпоинта. Предупреждение `[api] fallback to mock: <endpoint>` выводится один раз на эндпоинт до перезагрузки страницы. HTTP 401, 403, ошибки валидации и другие ответы сервера обрабатываются как ошибки. Локальные изменения применяются только к данным демо. Если ответ на изменяющий запрос потерялся в сети, сервер мог уже выполнить операцию.

В режиме разработки футер панели показывает `API: mock` при пустом `VITE_API_URL`, `API: live` при заданном адресе и `API: mixed` после первого перехода на мок. При входе через мок защищённые операции в этой сессии работают с данными демо.

### P1 на передачу команде бэкенда

- Веб-чат. Возвращать структурированный признак мошенничества, стабильные ID запроса и ответа, состояние ожидания и данные тикета. После утверждения или ответа специалиста история должна однозначно показывать отправленный результат.
- Маршрутизация демо. Зафиксировать ожидаемые результаты для фраз о переводе, отказе в восстановлении и мошенничестве. Сервер выбирает зелёный уровень при наличии подтверждённых цитат и достаточной уверенности. Жалоба сама по себе даёт жёлтый черновик, если отсутствуют основания для тикета, включая флаг `personal_case`. [Правила маршрутизации](../backend/app/pipeline/route.py#L25)
- Inbox, тикеты и оповещения. Сохранить связь по `message_id` и возвращать `response_id`, `ticket_id` и `ticket_number` там, где соответствующая запись существует. В деталях оповещения нужен ID обращения для перехода из аналитики.
- Сотрудники. Зафиксировать формат входа, проверить доступность встроенных ролей на живом стенде. Область видимости списков и работы с отдельной записью должна совпадать. [Начальные данные](../backend/app/db/session.py#L81)

Для проверок с разных адресов стенда потребуется разрешить их в [`CORS_ORIGINS`](../backend/app/config.py#L58). В конфигурации по умолчанию уже есть оба локальных адреса Vite на порту 5173.
